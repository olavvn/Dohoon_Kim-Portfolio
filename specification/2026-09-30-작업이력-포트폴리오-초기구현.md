# 포트폴리오 웹사이트 초기 구현 작업 이력

- 작업일: 2026-09-30
- 작업 내용: 입사 지원용 정적 포트폴리오 웹사이트 초기 구현
- 현재 단계: 로컬 정적 빌드 검증 완료, Vercel 배포 전

## 1. 작업 목표

채용 담당자와 현업 개발자가 지원자의 기술적 역량과 문제 해결 경험을 빠르게 파악할 수 있는 정적 포트폴리오 웹사이트를 구현한다.

이번 작업에서는 다음 목표를 우선했다.

1. `contents.md`에서 지정한 Notion 콘텐츠를 실제 포트폴리오 데이터로 구성한다.
2. `DESIGN.md`의 디자인 시스템을 포트폴리오 목적에 맞게 적용한다.
3. Next.js 기반의 정적 웹사이트로 구현한다.
4. 모바일과 데스크톱에서 사용할 수 있는 반응형 UI를 제공한다.
5. Vercel에 연결할 수 있도록 프로덕션 정적 빌드를 검증한다.

## 4. 구현한 콘텐츠

### 대표 프로젝트

다음 네 프로젝트를 기술적 의사결정과 수치 성과 중심으로 구성했다.

1. 안전고래
   - 사진 기반 안전 신고서 작성 AI 에이전트
   - FastAPI 기반 AI 서버, RAG, Langfuse 관측, EC2 배포
   - 사용자 30명 테스트에서 긍정 평가 80%
2. O’RAI
   - 라이브 커머스 AIOps 관측 데이터 파이프라인
   - Kinesis, Lambda, DynamoDB, S3, Glue, Datadog, Terraform 활용
   - 10초 단위 집계와 장애 시점 스냅샷 구성
3. NETLOG
   - 폐어망 수거와 업사이클링 공정 추적 플랫폼
   - Trace ID 기반 추적과 EC2/RDS 운영 구조
   - 기록 시간 약 30% 단축, 폐어망 추적률 약 80%
4. AnchorFlow
   - 실시간 앰비언트 MIDI 음악 생성 시스템
   - 생성과 재생 분리, 버퍼링, 백프레셔, wall-clock 스케줄링
   - 생성 속도 1.15배 개선 및 과목 Best Work 선정

프로젝트 카드에서는 요약과 주요 성과를 먼저 보여주고, `기술적 기여 자세히 보기`를 펼치면 문제, 기여, 결과를 읽을 수 있도록 구성했다.

## 7. 로컬에서 실행하는 방법

### 요구 환경

- Node.js 20 이상 권장
- npm

현재 구현과 검증에는 Node.js 24.5.0을 사용했다.

### 최초 설치

PowerShell 또는 터미널에서 프로젝트 루트로 이동한다.

```powershell
cd "D:\취업\Portfolio"
npm install
```

`package-lock.json`과 정확히 동일한 의존성을 설치하려면 다음 명령을 사용할 수 있다.

```powershell
npm ci
```

### 개발 서버 실행

```powershell
npm run dev
```

실행 후 브라우저에서 다음 주소를 연다.

```text
http://localhost:3000
```

터미널에서 `Ctrl+C`를 누르면 개발 서버가 종료된다.

### 포트 충돌 시

3000번 포트를 다른 프로그램이 사용 중이면 Next.js가 다른 포트를 안내할 수 있다. 포트를 직접 지정하려면 다음과 같이 실행한다.

```powershell
npm run dev -- -p 3001
```

이 경우 접속 주소는 `http://localhost:3001`이다.

## 8. 로컬 검증 방법

### ESLint

```powershell
npm run lint
```

### TypeScript

```powershell
npm run type-check
```

### 프로덕션 정적 빌드

```powershell
npm run build
```

빌드에 성공하면 `out/` 디렉터리에 정적 사이트가 생성된다.

### 정적 산출물 확인

개발 서버가 아니라 실제 정적 결과물을 확인하려면 임시 정적 서버를 사용할 수 있다.

```powershell
npx serve out
```

명령이 출력하는 로컬 주소로 접속한다. 일반적으로 `http://localhost:3000` 또는 사용 가능한 다른 포트를 사용한다.

`npx serve`는 최초 실행 시 패키지를 내려받을 수 있다. 별도 설치를 원하지 않으면 `npm run dev`로 화면을 확인하고 `npm run build`로 정적 출력 성공 여부를 검증한다.

## 11. Vercel 배포 전 남은 작업

1. 프로젝트 디렉터리를 Git 저장소로 초기화한다.
2. GitHub 등 원격 저장소를 연결하고 소스를 push한다.
3. Vercel에서 저장소를 가져와 Next.js 프로젝트로 배포한다.
4. Vercel URL에서 영상, 이미지, 링크, 모바일 화면을 확인한다.

현재 폴더에는 원격 Git 저장소와 Vercel 프로젝트가 연결되어 있지 않아 실제 배포는 진행하지 않았다.

### 대용량 영상 주의

`public/media/anchorflow-demo.mp4`는 약 97.5MB이며 전체 미디어는 약 165.7MB다. 배포 전 다음 중 하나를 권장한다.

- 영상 해상도와 비트레이트를 낮춰 압축
- YouTube 또는 별도 영상 호스팅 서비스 사용
- 짧은 미리보기 영상만 저장소에 포함하고 전체 데모는 외부 링크로 연결

## 15. 후속 수정: 프로젝트 상세 설명 모달

레퍼런스 사이트의 프로젝트 중심 정보 구조를 참고해 대표 프로젝트 카드의 상세 보기를 별도 모달로 개편했다. 사용자가 카드의 `프로젝트 상세 보기`를 선택하면 다음 내용이 정해진 순서로 표시된다.

1. `<개요>`: 프로젝트 배경, 목표, 담당 역할, 해결 과제
2. `<주요 작업>`: 직접 수행한 기술 작업과 설계 내용을 번호 순으로 표시
3. `<기술 스택>`: 프로젝트에 실제 사용한 언어, 프레임워크, 인프라 도구
4. `<성과>`: 정량 지표와 구현 결과

안전고래, O’RAI, NETLOG, AnchorFlow에는 각각 담당 역할과 프로젝트 맥락을 설명하는 문단을 추가했다. 상세 모달에서도 기존 미디어 슬라이드를 탐색할 수 있으며, GitHub 등 외부 프로젝트 링크를 마지막에 제공한다.

### 인터랙션 및 접근성

- 네이티브 `dialog` 요소를 사용한 모달
- `Esc`, 닫기 버튼, 모달 바깥 영역 클릭으로 닫기
- 모달 표시 중 배경 문서 스크롤 방지
- 프로젝트 제목을 모달의 접근 가능한 이름으로 연결
- 모바일에서는 전체 화면 상세 보기로 전환
- `prefers-reduced-motion` 설정 유지

### 콘텐츠 수정 위치

프로젝트 상세 텍스트는 `src/content/portfolio.ts`에서 수정한다.

- `role`: 담당 역할
- `overview`: 개요 설명 문단
- `problem`: 해결 과제
- `contributions`: 주요 작업
- `stack`: 기술 스택
- `metrics`, `results`: 성과
